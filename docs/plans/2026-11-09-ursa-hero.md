## 1. Current state (verified)

**No Ursa data or code.** `AbilityId` (`src/components.rs`, the `hero_generator:ability_enum` region) has no `Earthshock`, `Overpower`, `FurySwipes` or `Enrage`. `Overcharge` already exists and is a different id. Nothing in `data/`, `src/`, `scripts/` or `docs/` mentions Ursa.

**Reusable as is:**
- **Hero columns.** Every spec value fits the existing hero CSV columns, including `turn_rate` (Magnus G2) and melee at range 150 (`scale::is_melee_attack_range`). `HeroAttributes::apply_to` adds no attack damage, so the CSV `attack_damage` is the spec value, 44.
- **Dash.** `movement,dash` gives `DisplacementKind::Dash`: `value` = max distance and `duration` = time for the full distance (`displacement.rs` `plan_motion`). An own motion with a source fires `OnMovementEnd` at the final position, also when it stops at terrain or is interrupted by a stun, but not on death.
- **Area at the landing point.** `units_in_radius` on a trigger other than `on_cast` is centred on `AreaCenter::TriggerPoint` (`AbilityGenerator.py` `effect_context` only overrides `on_cast`). For `OnMovementEnd` that point is the landing position. The radius comes from `aoe_radius` (`AreaRadius::Ability`).
- **Slows.** `apply_status,slow` gives the id `earthshock_slow`, measured against base speed (Sniper G5/G6).
- **Timed attack speed.** `stat_modifier,attack_speed_flat` gives `StatusSpec::Modifier`, which changes stats when applied (`add_status_stat_delta`). The attack speed rating is clamped at 700: 100 + 18 + 400 = 518.
- **Attack-hit rows.** `on_attack_hit` with `trigger_unit` targets and attack metadata, as in Headshot. Damage under an attack context is `DamageKind::AttackBonus`: armor applies and it is eligible for lifesteal.
- **Dispel.** `AbilityEffect::Dispel { kind, strength }` produces `StatusChange::Dispel` (`status.rs`). Strong removes debuffs whose dispel type is `Basic` or `Strong` and leaves undispellable ones alone. The CSV form is `dispel,debuff` with `amount >= 0.5` meaning strong (`generator_common.py`).
- **Ordering.** Rows on one trigger run in `effect_index` order. Status events are applied in the order they were written (`apply_status_effect_events`), so in Enrage the dispel runs before the new buffs.

**Gaps:**
- **G1. A dash with no aim does not move.** `TargetType::NoTarget` aims at the caster (`targeting.rs`). `plan_motion` Dash uses `event.aim - from`, which is zero, so there is no motion and no `OnMovementEnd`. Vanguard's `AbilityMechanic::Dash` uses the same event.
- **G2. No charge-limited buff.** Statuses end only on expiry, dispel or removal by id. Nothing consumes a status per attack.
- **G3. No per-target stacking debuff and no stack-scaled damage.** `apply_status` refreshes a status by replacing it. `StatusEffect` has no stack count. `EffectScaling` has nothing that reads the target's statuses.
- **G4. No timed damage reduction.** The only incoming-damage factor is the permanent `CombatStats::incoming_damage_amp`. It has no status form.
- **G5. No status resistance.** It does not exist anywhere in the code.
- **G6. The strong-dispel CSV surface is untested and warns wrongly.** The `dispel` branch warns that `amount` is ignored and then reads `amount` to choose Strong.
- **(Existing limitation, not a gap.)** Attack point and backswing do not scale with attack speed. Under Overpower the attack cycle is roughly 0.3 + max(0.3, 0.328) ≈ 0.63 s.

## 4. Gap proposals

### G1. Dash along the facing when the aim is on the mover (movement layer)
- **Where.** In `displacement.rs` `plan_motion`, `DisplacementKind::Dash` arm: when `flat(event.aim - from).length() < MIN_TRAVEL` and `event.distance` is `Some(d)`, the direction is the mover's flat facing (`Transform::forward()`, with `-Z` as the fallback, the same as `effects::forward_point`) and the travel is `d`.
- **Why here.** This is the single place shared by the generated `movement,dash` effect and Vanguard's `AbilityMechanic::Dash`. It mirrors the bounded-teleport rule (QoP decision 3).
- **Behaviour change.** A point-targeted dash clicked on the hero itself (Vanguard Dash, Skewer) now dashes the full distance along the facing instead of doing nothing.
- **Tests (`displacement.rs`).** `dash_with_aim_on_mover_goes_forward_along_facing`, `dash_toward_an_aim_is_unchanged`, `dash_without_distance_and_aim_on_mover_does_nothing`.

### G2. Attack charges on timed stat modifiers (reusable; abilities and items)
- **CSV.** On a timed `stat_modifier` row, `amount` is the number of attack charges. Blank means not charge-limited. Level list of whole numbers ≥ 1. Rejected on `passive`, `while`, `while_toggled` rows and on resource stats.
- **Rust (`definition.rs`).** `StatusSpec::Modifier` gains `attack_charges: RankValue` (ZERO = unlimited). `build` sets `StatusEffect.attack_charges` (`u32`). Allowed generated diff: every existing Modifier site gains `attack_charges: RankValue::ZERO`.
- **Rules (`status.rs`).** New `StatusChange::ConsumeAttackCharge` decrements every live status of the target with `attack_charges > 0`; at 0 the status is removed through `remove_statuses` and reported `Expired`. New system `status::consume_attack_charges` reads `BasicAttackReleaseEvent` with `extra == false` and writes one event per release. Scheduled next to `attack_triggers`; mirrored in test apps.
- **Timing.** A charge is used at attack release (including misses). All X attacks get the bonus; the (X+1)th does not. Extra attacks never use a charge. A recast resets charges.
- **Tooltip.** "for the next N attacks".
- **Tests.** `attack_charges_are_consumed_per_release_and_revert_at_zero`, `extra_attacks_do_not_consume_charges`, `recast_resets_attack_charges`, `charged_status_still_expires_on_duration`, item/ability parity.

### G3. Stacking debuff and stack-scaled damage (reusable; abilities and items)
- **CSV, status.** `apply_status,stacks` with `duration` required. Id `<owner>_stacks`. Debuff with `DispelType::None` (U7).
- **CSV, scaling.** `scaling_type=target_stacks`, `scaling_value` = offset (0 or 1). Amount = `value(rank) × (stacks of <owner>_stacks on target + offset)`. Rejected without an `apply_status,stacks` row on the same owner.
- **Rust.** `StatusEffect.stacks: u32`; `StatusSpec::Stacks { id }` builds `stacks: 1`; `apply_status` merges `new.stacks += old.stacks` on same-id replacement (duration refreshed). `StatusEffects::stacks(id)`. `EffectScaling::TargetStacks { id, offset }`; `scaled_amount` returns `None` for ≤ 0.
- **Offset (U4).** Damage row reads the pre-hit count; offset 1 makes the hit count its own stack: hit 1 = 1×, hit 2 = 2×, … (Dota-like).
- **Known edges.** Debuff-immune targets get no new stack but still take `(old+1)×`. Stacks are per ability id, not per Ursa entity.
- **`runtime_status_id` / `held_status_id`.** Support `_stacks`; `remove_status,stacks` rejected with a hint.
- **Tests.** `stacking_status_adds_and_refreshes`, `stacks_are_lost_on_expiry`, `target_stacks_scales_by_stacks_plus_offset`, `different_targets_keep_separate_stacks`, item/ability parity.

### G4. Damage-reduction status (gameplay rule)
- **CSV.** `apply_status,damage_reduction`, percent from `amount` (0 < p ≤ 100). Buff id `<owner>_damage_reduction`.
- **Rust.** `StatusSpec::DamageReduction { id, percent }`; `StatusEffects::damage_taken_factor()` = Π(1 − r). `combat::resolve_incoming_damage` gains `taken_factor`, applied next to `incoming_damage_amp` after mitigation.
- **Coverage.** All damage types including pure, DoT ticks, reflection, burns. Shields still absorb the pre-armor amount (U8).
- **Tests.** `damage_reduction_scales_post_mitigation_damage_for_all_types`, `two_damage_reductions_stack_multiplicatively`, `damage_reduction_ends_on_expiry`.

### G5. Status-resistance status (gameplay rule)
- **CSV.** `apply_status,status_resistance`, percent (0 < p ≤ 100). Buff id `<owner>_status_resistance`.
- **Rust.** `StatusSpec::StatusResistance { id, percent }`; `status_resistance_factor()` = Π(1 − r). In `apply_status_effect_events` (`Apply`), for finite hostile debuffs, scale `remaining` by the factor; recompute `dot_ticks_left` for ticking burns.
- **Scope.** Durations only; slow amounts unchanged. Self/ally debuffs and buffs untouched.
- **Tests.** `status_resistance_shortens_only_hostile_debuffs`, `status_resistance_recomputes_ticking_burn_ticks`, `status_resistance_has_no_effect_after_it_ends`.

### G6. Strong-dispel CSV cleanup (generator only)
- Stop warning about `amount` on `dispel,buff|debuff`; document "`amount` 1 = strong dispel". Add a valid example row and a unittest asserting `DispelStrength::Strong` with no warning.

### G7 (optional). A refused own dash still reports `OnMovementEnd`
- When an `Own` dash/charge with a source is refused (cannot move, or no plan), write `OnMovementEnd` at the mover's position with no affected/trigger units. Lets Earthshock slam in place when rooted (U5). No effect on Skewer / bull_rush.

- Left alone: attack point/backswing don't scale with AS; stacks per ability id; shields soak before reduction; Earthshock ring drawn at take-off.

## 13. Implementation notes (2026-11-09)

**Remaining limitations**
- Two attack hits in the same frame read the same stack count (stacks are applied by the status event after the damage row runs).
- Stacks are per ability id, not per Ursa entity (two Ursas share one `fury_swipes_stacks` count on a target).
- Attack point and backswing still do not scale with attack speed, so Overpower's attack cycle is about 0.63 s.
- The Earthshock ring is drawn at the take-off point.
- Status resistance also shortens Skewer's bound stun and cyclones (U10), and a refused dash now reports `on_movement_end` for every own dash (Skewer, bull_rush) with no contacts, which no existing row consumes.
